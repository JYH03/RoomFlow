# Day 13 — 동시성 제어

## 해결할 문제

`예약 있나 확인 → 없으면 저장`만으로는 동시 요청 두 개가 모두 빈 상태를 보고 같은 방에 예약을 만들 수 있습니다. JVM의 synchronized는 서버 인스턴스가 둘이면 서로를 보호하지 못합니다.

취소된 기록까지 막는 `UNIQUE(room_id, start_at)`도 사용할 수 없습니다. 현재 모델은 취소 이력과 새 예약을 함께 저장해야 하기 때문입니다.

## 선택: 사용자와 방 행의 비관적 잠금

사용자 요청은 다음 순서로 처리합니다.

1. 트랜잭션 시작 (READ_COMMITTED).
2. 사용자 행에 PESSIMISTIC_WRITE 잠금.
3. 대상 방 행에 PESSIMISTIC_WRITE 잠금.
4. 잠금 취득 후 예약·제안·대기 상태를 읽고 검증.
5. 상태 변경과 다음 제안 생성 후 함께 커밋.

사용자 잠금은 같은 사용자가 서로 다른 방을 동시에 예약/수락하는 것을 막습니다. 방 잠금은 같은 방의 예약·대기 순번·승급을 직렬화합니다. MySQL에서는 잠금이 트랜잭션 완료까지 유지됩니다.

취소·수락처럼 ID만 전달되는 요청은 먼저 **방 ID만** 조회한 다음 방을 잠그고 엔티티를 불러옵니다. 잠금 전에 읽은 오래된 엔티티가 영속성 컨텍스트에 남는 것을 피하기 위해서입니다.

READ_COMMITTED를 명시해 잠금을 기다린 뒤 수행하는 조회가 이전 요청의 최신 커밋을 읽게 합니다. Open Session in View도 끕니다.

## 스케줄러와 잠금 순서

자동 처리는 사용자 행을 잠그지 않고 **방 하나만** 잠급니다. 다른 사용자의 예약을 확정하지 않으며 제안 생성만 하기 때문입니다. 제안 수락 시에는 사용자·방 잠금과 사용자 중복 검사를 다시 수행합니다.

대상 ID 목록만 조회하고 각 ID를 별도 서비스 트랜잭션으로 처리합니다. 배치 전체를 한 트랜잭션에 넣어 여러 방을 잡지 않습니다. 여러 서버에서 같은 항목을 처리해도 잠금 후 상태를 재확인해 멱등적으로 동작하도록 구현했습니다. 검증은 한 JVM의 여러 스레드와 실제 MySQL 연결을 사용했으며 다중 서버 부하 검증은 별도입니다.

## 보호하는 규칙

- 동일 방의 겹치는 활성 예약은 최대 하나.
- 동일 사용자의 겹치는 활성 예약은 최대 하나.
- 순번 생성은 방 잠금 아래 max + 1. DB에도 방·시작·순번 복합 UNIQUE 유지.
- PENDING 제안은 일반 예약으로 선점 불가.
- 만료된 PENDING도 만료·다음 승급 트랜잭션이 끝나기 전까지 보호.
- 중복 취소·수락·거절은 첫 성공만 반영.
- 스케줄러 재실행은 이미 처리된 상태를 다시 승급하지 않음.

## 확인한 시나리오

동시 방 예약 10건, 같은 사용자 다른 방 예약, 대기 등록 10건, 동일 대기 중복 등록, 중복 취소, 중복 수락, 수락 대 거절, 수락 대 대기 취소, 여러 만료 작업, 여러 노쇼 작업, 체크인 대 유지보수, 같은 사용자의 다른 방 제안 동시 수락을 테스트합니다.

실행은 `gradlew.bat test`(H2)와 `gradlew.bat mysqlTest`(실제 MySQL, 임시 DB)입니다. MySQL 테스트는 ORM 생성 DDL이 아니라 SQL/schema.sql을 실행하고 Hibernate validate로 엔티티와의 호환성도 검사합니다.

## 트레이드오프·한계

- 같은 방의 다른 시간대 요청도 순차 처리됩니다. 13실 MVP에서는 구현·검증의 단순성을 우선했습니다.
- 대기 순서는 DB 잠금 획득 후 등록된 순서이지, 네트워크 요청 도착 시각의 절대적 순서가 아닙니다.
- DB 직접 INSERT 등 이 잠금 규약을 우회하는 쓰기는 보호하지 못합니다.
- 잠금 타임아웃/교착은 409로 응답하고 상태 조회 후 재시도하도록 안내합니다.
- 대량 사용자 부하·분산 서버·장애 복구 성능 검증은 하지 않았습니다.
- 슬롯별 행 잠금, 페이지네이션, 운영 지표는 확장 단계의 과제입니다.

참고: [Spring Data JPA의 잠금](https://docs.spring.io/spring-data/jpa/reference/4.0/jpa/locking.html).
